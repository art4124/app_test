Prototype privacy notes

Testing build

Use fictional information in this web prototype.

This build exists to test product flows before the native iOS version. It is not the final production security architecture and should not be treated as a medical record system.

What this prototype does

  • Stores Vune state only in the current browser.
  • Encrypts that local state with AES-GCM using a key derived from the passcode you enter.
  • Uses no advertising SDKs, analytics SDKs, cloud database, or external AI API.
  • Does not require an account, email address, phone number, or name.
  • Maintains an encrypted Recovery Key backup in this browser for local restoration.
  • Hides the interface when the browser tab becomes hidden.

Important prototype limitations

  • Browser storage and browser passcode handling are not a substitute for iOS Keychain, Secure Enclave, or native device protections.
  • Browser extensions, compromised devices, malicious browser software, or future code changes can create risks that encryption at rest alone cannot prevent.
  • The Assistant in this build is a local rule-based UX prototype. It is not the planned native on-device AI implementation.
  • No browser application should promise absolute security.

Data deletion

Deleting the active browser copy resets Vune but keeps its encrypted Recovery Key backup so the vault can be restored during testing. Vune also provides a separate permanent-delete control that removes both the active vault and the local recovery backup.

Before TestFlight

The iOS build will replace browser-specific protections with native secure storage, platform authentication, native database protections, and the final Vune privacy/security review.
